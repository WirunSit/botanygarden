# 🌿 พฤกษาพุทธมงคล — ระบบจัดการพรรณไม้ งานสวนพฤกษศาสตร์โรงเรียน

ระบบตาม [แผนพัฒนา](botanical-garden-system-plan.md) — หลังบ้านเป็น **Google Apps Script + Google Sheet + Google Drive**
หน้าเว็บใช้บนมือถือเป็นหลัก นักเรียนบันทึกต้นไม้ทีละขั้น ครูตรวจและอนุมัติ ระบบออกรหัสพรรณไม้ให้อัตโนมัติ

---

## 1. ลองใช้ในเครื่องก่อน (โหมดทดลอง — ไม่ต้องตั้งค่าอะไร)

ต้องมี [Node.js](https://nodejs.org) แล้วรัน:

```bash
node dev/server.js
```

เปิด <http://localhost:8080/frontend/> — ข้อมูลตัวอย่างเก็บในเบราว์เซอร์เครื่องนั้น (AI เป็นคำตอบสุ่ม)

| ชื่อผู้ใช้ | รหัสผ่าน | บทบาท |
|---|---|---|
| admin | admin1234 | ผู้ดูแลระบบ |
| teacher | 123456 | ครู |
| 10001 | 123456 | หัวหน้ากลุ่ม |
| 10002 | 123456 | นักเรียน (มีงานถูกส่งกลับ) |
| 10004 | (เว้นว่าง) | นักเรียนเข้าครั้งแรก |

> โหมดทดลองใช้โค้ดหลังบ้านชุดเดียวกับบน Apps Script จริง (รันในเบราว์เซอร์แทน)

## 2. ติดตั้งใช้งานจริง

### ขั้นที่ 1 — สร้างไฟล์ติดตั้ง
```bash
node tools/build.js
```
ได้โฟลเดอร์ `dist/apps-script/` (ไฟล์ `.gs` 13 ไฟล์ + `Index.html` + `appsscript.json`)

### ขั้นที่ 2 — สร้าง Google Sheet และวางโค้ด
1. สร้าง Google Sheet ใหม่ ตั้งชื่อเช่น `ทะเบียนพรรณไม้ พุทธมงคล` (ใช้บัญชี Google ของครูผู้ดูแล)
2. เมนู **ส่วนขยาย → Apps Script**
3. **การตั้งค่าโปรเจกต์ (⚙️)** → ติ๊ก *แสดงไฟล์ Manifest "appsscript.json"* → เปิด `appsscript.json` แล้ววางเนื้อหาจาก `dist/apps-script/appsscript.json`
4. สร้างไฟล์สคริปต์ (➕ → สคริปต์) ให้ **ชื่อตรงกับไฟล์** แล้ววางเนื้อหา:
   `Platform`, `Utils`, `Auth`, `Plants`, `Photos`, `AI`, `Review`, `Admin`, `Reports`, `Field`, `Content`, `Setup`, `Code`
   (ลบเนื้อหาเดิมใน `Code.gs` ก่อนวาง)
5. สร้างไฟล์ HTML (➕ → HTML) ชื่อ **`Index`** แล้ววางเนื้อหาจาก `dist/apps-script/Index.html`
6. กด 💾 บันทึก

> ถ้าคล่อง command line ใช้ [clasp](https://github.com/google/clasp) `clasp push` จากโฟลเดอร์ `dist/apps-script/` แทนการคัดลอกทีละไฟล์ได้

### ขั้นที่ 3 — ตั้งค่าครั้งแรก
1. เลือกฟังก์ชัน **`setup`** ในแถบด้านบน → กด **เรียกใช้** → อนุญาตสิทธิ์ (Sheet, Drive, เรียกบริการภายนอกสำหรับ AI)
2. ระบบสร้างชีตทั้งหมด รายการตัวเลือก ค่าตั้งต้น โฟลเดอร์รูป `BuddhamongkolFlora_Photos` และบัญชี `admin`
3. กลับไปที่ชีต รีเฟรช จะมีเมนู **🌿 พฤกษาพุทธมงคล** → เลือก **เปิดสำรองข้อมูลอัตโนมัติทุกคืน**

### ขั้นที่ 4 — เผยแพร่เป็นเว็บแอป
1. **ทำให้ใช้งานได้ → การทำให้ใช้งานได้รายการใหม่ → ประเภท: เว็บแอป**
2. ดำเนินการในฐานะ: **ฉัน** · ผู้มีสิทธิ์เข้าถึง: **ทุกคน**
3. คัดลอก URL ที่ลงท้ายด้วย `/exec`

> แก้โค้ดภายหลัง: **จัดการการทำให้ใช้งานได้ → ✏️ → เวอร์ชัน: เวอร์ชันใหม่** เพื่อให้ URL เดิมใช้ต่อได้
>
> **อัปเดตจากรุ่นก่อน**: วางไฟล์ `.gs` ทั้งหมดใหม่ (มีไฟล์ใหม่ `Field.gs`, `Content.gs`) + `Index.html` + `appsscript.json` แล้วรัน `setup` อีกครั้ง 1 ครั้งเพื่ออนุญาตสิทธิ์ส่งอีเมล
> (ถ้าลืมรัน ระบบจะสร้างชีต/คอลัมน์/ตัวเลือกใหม่ให้อัตโนมัติในคำขอแรก ข้อมูลเดิมไม่หาย)

### ขั้นที่ 5 — ตั้งค่าในระบบ
เปิด URL → เข้าสู่ระบบด้วย `admin` (เว้นรหัสผ่านว่าง) → ตั้งรหัสผ่านทันที แล้วไปที่ **⚙️ จัดการระบบ**
- **ตั้งค่า**: รหัสไปรษณีย์โรงเรียน (จำเป็นสำหรับรหัสพรรณไม้ `7-XXXXX-YYY-ZZZ`), ลิงก์หน้าเว็บสำหรับ QR, Gemini API Key ([aistudio.google.com](https://aistudio.google.com) → Get API key), ตรวจชื่อรุ่น Gemini ที่ใช้ได้ล่าสุด
- **โซน/อาคาร**: เลื่อนแผนที่ไปที่โรงเรียน → *ใช้ตำแหน่งนี้เป็นจุดเริ่มต้น* → วาดขอบเขตโรงเรียน → วาดโซน → วาดอาคาร (แตะตามมุมอาคาร ใส่ความสูง) สำหรับแผนที่ 3 มิติ
- **เส้นทางเรียนรู้ / ภารกิจ**: ครูสร้างได้ที่ จัดการระบบ (ครูผู้ช่วยก็ใช้ได้)
- **ภาพจากโดรน (ไม่บังคับ)**: ถ้ามีภาพออร์โธโมเสกของโรงเรียนที่แปลงเป็นไทล์ XYZ แล้ว ใส่ลิงก์รูปแบบ `https://.../{z}/{x}/{y}.png` ที่ ตั้งค่า → `imagery_url`
- **นำเข้ารายชื่อ**: คัดลอกจาก Excel วางได้เลย (เลขประจำตัว, ชื่อ-สกุล, ห้อง, เลขที่, กลุ่ม, ...)
- ถ้ามีทะเบียนพรรณไม้เดิม: ครูกรอกรหัสเดิมได้ในขั้น "วัดขนาด" (ช่องรหัสประจำต้น) และในหน้าแก้ไขชนิด (รหัสชนิด) ระบบจะออกรหัสใหม่ต่อจากเลขสูงสุด ไม่ทับของเดิม

### ทางเลือก B (แนะนำเมื่อใช้จริง) — ฝากหน้าเว็บบน GitHub Pages
หน้าเว็บที่รันใน Apps Script อยู่ใน iframe ของ Google ซึ่ง**อาจใช้ GPS ไม่ได้**ในบางเครื่อง (ยังปักหมุดเองบนแผนที่ได้)
ถ้าต้องการ GPS เต็มที่และ URL สั้น:
```bash
node tools/build.js --api https://script.google.com/macros/s/XXXX/exec
```
อัปโหลดไฟล์ทั้งหมดใน `dist/web/` (`index.html`, `sw.js`, `manifest.webmanifest`, `icon.svg`) ขึ้น GitHub Pages (หรือ Firebase Hosting) แล้วตั้ง "ลิงก์หน้าเว็บสำหรับ QR Code" เป็น URL นั้น
ทางเลือกนี้ยังทำให้ **ติดตั้งเป็นแอปบนมือถือ** (เมนูเบราว์เซอร์ → เพิ่มลงหน้าจอหลัก) และ **ใช้งานออฟไลน์** ได้ — ทั้งสองอย่างใช้ไม่ได้เมื่อเปิดผ่าน URL ของ Apps Script

## 4. ข้อควรทราบ

- **สิทธิ์รูปใน Drive**: เพื่อให้หน้าเว็บแสดงรูปได้ ระบบตั้งรูปเป็น "ทุกคนที่มีลิงก์ดูได้" ตั้งแต่ตอนอัปโหลด (ลิงก์เดาไม่ได้ และหน้าสาธารณะแสดงเฉพาะรูปที่อนุมัติ) — ถ้าโดเมนโรงเรียนห้ามแชร์ลิงก์ ระบบจะส่งรูปผ่าน API แทนอัตโนมัติ (ช้ากว่า)
- **เข้าครั้งแรก**: ใครรู้เลขประจำตัวก็ตั้งรหัสผ่านแทนนักเรียนได้ก่อน — ควรให้นักเรียนทุกคนตั้งรหัสผ่านพร้อมกันในคาบแรก ถ้ามีปัญหาครูกด "รีเซ็ตรหัส" ได้
- **AI**: ตรวจชื่อรุ่นโมเดลใน *ตั้งค่า → gemini_model* และเงื่อนไขโควต้า/การใช้ข้อมูลของบริการฟรีก่อนเปิดใช้ ระบบส่งเฉพาะรูปต้นไม้ ไม่ส่งข้อมูลนักเรียน
- **รูปแบบ ก.7-003 / ก.7-005 / รหัสพรรณไม้**: อิงตามแผน ควรเทียบกับคู่มือ อพ.สธ. ฉบับที่โรงเรียนใช้อีกครั้ง
- วันที่ถ่ายใช้เวลาของไฟล์รูป (ยังไม่อ่าน EXIF)
- **ออฟไลน์**: ข้อมูลในกล่องรอส่งอยู่ในเบราว์เซอร์เครื่องนั้น — ห้ามล้างข้อมูลเบราว์เซอร์ก่อนส่งเสร็จ (ดูจำนวนที่ปุ่ม 📤 แถบบน) · ภาพแผนที่ออฟไลน์ใช้ได้เฉพาะบริเวณที่เคยเปิดดูตอนมีเน็ต · ระหว่างออฟไลน์ข้ามการตรวจต้นซ้ำและใช้ AI ไม่ได้
- **คาร์บอน** เป็นค่าประมาณสำหรับการเรียนรู้ คำนวณเฉพาะไม้ต้น/ไม้พุ่มที่มีเส้นรอบวงและความสูง (ไม่รวมปาล์ม ไผ่ ไม้เลื้อย ไม้ล้มลุก) — อ้างอิงสมการแสดงในหน้าต้นไม้
- **อีเมล** ใช้โควต้า MailApp ของบัญชีครู (บัญชี Gmail ทั่วไปประมาณ 100 ฉบับ/วัน) — การแจ้งเตือนทางอีเมลปิดไว้เป็นค่าเริ่มต้น
- **แผนที่ 3 มิติ** ต้องใช้ WebGL — มือถือรุ่นเก่า/หน่วยความจำน้อยระบบจะแนะนำแผนที่ 2 มิติแทน
